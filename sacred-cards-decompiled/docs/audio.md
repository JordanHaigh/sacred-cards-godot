# Audio recovery — AY7E USA Rev. 00

## Local output

`build/assets/audio/index.html` is a searchable listening gallery. It contains:

- 58 music entries and 76 effects as 48 kHz stereo, 16-bit PCM WAV files.
- 134 MIDI conversions, with original song-table IDs retained in filenames.
- `instruments.sf2`: 55 voice banks, matched by each MIDI's bank-select events.
- 139 PCM samples, original signed 8-bit bytes and headers, plus individual WAVs.
- Seven raw 16-byte PSG waveforms; square/noise sounds are generated by the driver.
- All 225 table slots in `catalog.csv` and `manifest.json`, including 91 zero-track
  slots. Zero-track does not mean unused: slot 000 is the game's stop-music command.
- Original tables, bank windows, sequence regions, and a contiguous audio-data
  region from `0x9DF52C` to `0xD2A6E4` (exclusive). The contiguous region also keeps
  local patterns that precede track entry points, unused bytes, and alignment gaps.

Song titles and effect names have not been guessed. Music/effect classification
follows player 0 versus the other players; it can include jingles among music.
The gallery links 58 scenes to their default music and lists 27 configuration
variant overrides. Scene 51 variant 4 selects song 000, stopping music.

## ROM evidence

| Offset / address | Meaning |
| --- | --- |
| `0x9F42C0` | 225 song table records: header pointer, u16 player, u16 secondary player |
| `0x9F423C` | 11 player records, 12 bytes each |
| `0x080379B4` | Song-number start: indexes song table, then player table, calls `0x080380E8` |
| `0x08037930` | Driver initialization; mode word `0x0097FC00` at `0x37998` |
| `0xD1278` | 225 two-byte game action categories; second byte is zero in this ROM |
| `0x08021EB0` | Returns the category byte at `table + (u16)song * 2` |
| `0x08021E50` | Game audio dispatcher; categories 1/5 start-or-change, 2/3 start, 4 stop |
| `0xD4C87C` | 58 default scene music IDs, u16 |
| `0xD4C8F4` | 27 `(s16 scene, s16 variant, s16 song)` overrides plus -1 terminator |
| `0x08031144` | Searches overrides before selecting default scene music |

Initialization gives PCM volume 15, reverb 0, frequency index 7 (21,024 Hz),
12 PCM channels, DAC configuration 9. Individual sequences may change reverb.
Player track capacities are 16, 1, 1, 2, 2, 3, 4, 2, 1, 1, 5.
Song headers contain track count, block count, priority, reverb, bank pointer,
and track pointers. The 55 referenced banks use 12-byte instrument definitions,
including key splits and percussion children. PCM headers store mode, middle-C
frequency multiplied by 1,024, loop start and sample length. The 139 extracted PCM records cover the sample
region from `0x9F49CC` through `0xCF8B2B` (exclusive), with at most four padding
bytes between consecutive records.

`src/audio_dispatch.c` recovers the dispatcher, category accessor and scene-music
selection as semantic C. External tables and driver calls remain unresolved
link dependencies. These routines have been inspected against assembly, but are
not execution-compared or compiler-matched.

## Reproduction

```sh
make rip-audio
```

This builds pinned third-party code under ignored `build/`, then extracts and
renders all populated entries. It requires a C++20 compiler, Git, FFmpeg, and
libsndfile headers/library. The supplied build script uses this machine's
Homebrew paths `/opt/homebrew/include` and `/opt/homebrew/lib`. Downloads need
network access; the ROM is read locally and is never uploaded.

`make rip-assets` performs standard-library raw audio extraction alongside the
visual assets. It preserves an existing rendered audio export. To refresh
catalog metadata using existing successful conversions:

```sh
python3 tools/rip_audio.py "Yu-Gi-Oh! - The Sacred Cards (USA).gba" --reuse-converted
```

## Renderer and conversion limits

WAVs use [agbplay](https://github.com/ipatix/agbplay), commit
`d209cce0449edfa61bbf15a9d22735ddfe09dd4f`, through a small offline frontend.
The upstream scalar resamplers are selected for Apple Silicon; archive loading,
GUI and global configuration are omitted. The build uses pinned fmt 11.2.0 and
Boost.Math 1.88.0 headers. Original third-party sources and licenses stay beside
the generated binaries.

The renderer's `maxLoops=2` counts jumps on track zero and fades after the third
qualifying jump. It is a renderer setting, not a recovered game stop time. Songs
without loops run to their end, including release tails. A ten-minute ceiling
and an execution timeout guard malformed sequences; **none of the 134 entries
hit those limits or failed conversion in this export**. All produced nonzero
output. Uniform gain 0.95 leaves headroom before conversion from floating-point
mixing to 16-bit WAV. Total output is roughly 172 minutes including repeats and
tails, approximately 2 GB.

This is software-rendered playback, not a hardware recording or a bit-exact
emulation of the original mixer. agbplay does not enforce the original PCM
channel limit; its resampling, envelopes and mixing can differ from hardware.
No listening comparison against console/emulator playback has been performed.

MIDI and SoundFont use [GBA Mus Ripper](https://github.com/CaptainSwag101/gba-mus-ripper),
commit `98ddff94a53512f57b7a4883ae4c3f3a20ac18a5`. The local generated build fixes
an end-iterator dereference, bounds AY7E's final voice bank to its 16 entries,
and uses literal format strings for diagnostic output. SoundFont PSG/noise
approximations use that tool's bundled synthesis data, not newly extracted
PCM. MIDI conversion preserves original velocity/controller values and adds
GS channel-mode messages. It is not a lossless representation of MP2K behaviour.
Use the original sequences and headers for further reverse engineering.

Individual sample WAVs play once at their header's middle-C rate rounded to an
integer. Fixed-rate playback, note pitch, ADSR and looping belong to the engine;
loop positions remain in the manifest rather than embedded in those WAVs.

## Audio call-site map

`tools/map_audio_usage.py` consumes the expanded listing and direct call edges,
propagating constants conservatively within individual Thumb basic blocks.
It writes `audio/usage.html`, `usage.csv` and `usage.json` with call addresses,
resolved IDs, unresolved calls, instruction evidence and listing provenance.
The HTML links existing WAV files; it does not rerender audio.

Demonstrated contexts include track 003 on city-map menu entry (08000958),
track 046 on name-entry initialization (0800182E), and effect 054 on two
name-entry mode-change paths (080018DC and 0800192E). These labels describe
uses and are not official sound titles. The same effect may occur elsewhere.

Run `make map-audio` to regenerate disassembly and the usage map. `make rip-assets`
also refreshes it if disassembly exists. Static listing coverage is partial,
includes heuristic seeds, and does not establish that every call executes.
Dynamic song IDs, script operands and indirect calls need further tracing;
absence from the map does not imply unused audio.

The usage gallery now also imports 474 static @8 references from decoded scene
scripts and links back to their nodes. Language-specific duplicates and commands
suppressed by the native handler are marked; they are not counted as distinct
sounds or runtime observations. Newly recovered callback/switch code also expands
the direct-call map; current totals are generated in `usage.json` and `usage.html`.
